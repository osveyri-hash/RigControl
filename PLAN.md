# RigControl → Rust: план и статус

Исходник: RigControl 2.17.3 (C#, WPF, .NET 8), около 20,7 тыс. строк в 50 файлах .cs/.xaml.
План составлен командой `rust-anything analyze` (v3.0.0), полный вывод лежит в ANALYZE.md.

## Что уже портировано (крейт rigcontrol-core)

| C# | Rust | Статус |
| --- | --- | --- |
| Ak820Protocol.cs | src/protocol.rs | портирован 1:1, есть юнит-тесты |
| LightEffects.cs | src/effects.rs | портирован 1:1, есть юнит-тесты |
| KeyPaint.cs | src/keypaint.rs | портирован 1:1, есть юнит-тесты |
| ColorWheel.cs (только HSV и Hex) | src/color.rs | портирован; сам круг — WPF, уйдёт в UI |
| Ak820Device.cs + HidInterface.cs | src/device.rs | эффекты, раскраска, часы, живые кадры; без заливки экрана и IsWiredPresent |
| — | src/bin/rigcontrol.rs | консольная утилита rigcontrol.exe — проверена на клавиатуре |
| Cooler/CoolerLcd.cs + часть LcdRender.cs | src/cooler.rs | экран помпы: картинки, гифки, заливка цветом (JPEG и RGB565); без сцен с датчиками |

На что обращал внимание при переносе:
- Math.Round в .NET округляет банковски, поэтому в Rust стоит round_ties_even, а не round.
- (byte)x для double в C# обрезает дробь; в Rust это `as u8`, после такого же Clamp.
- Деление и остаток (/ и %) у int, long и double ведут себя одинаково в C# и Rust (знак берётся от делимого).
- Где C# бросает исключение (пустой массив, Clamp с min > max), Rust паникует или возвращает Err.
- Вместо DateTime функция принимает DateTimeParts, чтобы ядру не нужны были внешние крейты.

## Ограничения rust-anything для C#
В v3.0.0 для C# работают только `app record`, `app replay` и front door, причём для CLI и ASP.NET.
Порт по модулям через P/Invoke автор обещает в следующих версиях. RigControl — это WPF-окно,
которое работает с USB HID, поэтому записать эталон через `app record` нельзя. Сверять порт
с оригиналом придётся характеризационными тестами: прогнать одни и те же входы через C# и
через Rust и сравнить байты.

## Следующие шаги (порядок по плану analyze)
1. ImageFrames.cs, GifFrames.cs: декодирование картинок и гифок (крейты image и gif вместо WPF Imaging).
2. HidInterface.cs → крейт hidapi; затем Ak820Device.cs, Ak820Dongle.cs, Mouse/, Argb/AuraUsb.cs.
3. Cooler/LcdScene, LcdItem, LcdThemes (сцены с датчиками на экране помпы) и Telemetry. LibreHardwareMonitor на Rust прямой замены не имеет:
   нужны WMI и драйвер (например, обёртка над PawnIO или WinRing0) или C#-хелпер как отдельный процесс.
4. Settings, RigProfile, LogFile, Autostart, TrayIcon (serde_json, крейты winreg и tray-icon).
5. Интерфейс. Около 8 тыс. строк XAML и MainWindow.*.cs придётся писать заново
   (Slint, egui или Tauri): автоматически XAML не переносится.

## v21 — заряд клавиатуры и battery.log

Статус: написано, не компилировалось в песочнице.

- Баг: заряд «зависал» (57 % при реальных 60 %). Причины: старое значение из прошлого опроса оставалось
  в `stray_battery` и возвращалось без нового запроса; из нескольких ответов брался первый (запомненный донглом).

  пишутся только изменения, до 100 КБ.
